# L3 · Build Loop

Специфіка поверх `loop-passport.md`. Докази, якими куплені ці правила, лежать у `decisions-log.md` за датами — тут лише сама поведінка.

## Гейти циклу

Умови зупинки живуть у `gates.json` продукту, а не в цьому тексті. Їх рахує `strw-run`, тому «гейт-блок назвав чотири умови замість шести» більше не може статися (04.08).

Вісім гейтів: `tests · lint · contract · kmp · deps · secrets · tracking · human_smoke`.

**`human_smoke` — повноцінний гейт.** Година живого користування 06.08 дала три дефекти, яких автотести не ловлять за побудовою. Коли до екрана руками не дійти — двоактовий XCTest проти живого стеку, зі `skippedTests: 0`, перевіреним через `xcresulttool` (04.08).

## Правила циклу

1. **Продовження, не перезапуск.** Цикл починається з `state.md`: Next + зауваження reviewer'а. `Tried & failed` — заборона повторювати тупикові підходи.
2. **Tests-first.** AC з PRD → падаючі тести → реалізація під них. Тести написані під готовий код контрактом не вважаються.
3. **Worktree-ізоляція.** Кожна паралельна фіча — власний worktree і власний DerivedData.
4. **Дизайн-трек паралельний.** Блокує брак токенів чи макета — engineer будує логіку без UI.
5. **Security перед checker'ом.** dep-audit, верифікація нових залежностей, security-review по diff.
6. **Кожен мерж проходить незалежну агентську перевірку — умова, не опція** (рішення CEO 2026-08-08, ратифіковано в decisions-log). Перевірка коду — агентська, не CEO: мерж без чекера, поданий людині на затвердження, просить згоди на те, чого вона не може оцінити. До CEO йде рішення, а не диф — список у company-context.md, принцип 5 (єдине джерело). Вимір: з ~11 циклів із чекером 10 дали REQUEST CHANGES із реальними знахідками. Мерж без чекера — лише явний виняток із записом у `decisions-log.md`: «PR #N · без checker · причина · що прийнято на віру».

6a. **Великий або незворотний мерж перевіряють КІЛЬКА рев'юерів, принаймні один — іншого вендора** (рішення CEO 2026-08-08): модель, спільна для maker і checker, ділить і сліпі зони — потрібні *інші* очі, не «більше очей».

   **Великий — за критеріями, не на око.** Досить одного: диф чіпає `contract/**` · крипто, обмін ключами простору чи міграції БД · сам вимірювальний інструмент (`gates.*.template.json`, `scripts/*-check.sh`, `dep-allowlist.txt`) · залежність `sends-user-data` · закриває віху · понад ~400 рядків чи ~15 файлів.

   **Склад:** внутрішній чекер — модель ЗАВЖДИ інша, ніж у maker'а, класу не слабшого, ефорт вище типового («сильніша, але та сама» скасувала б принцип 6; збіг ріже budget-gate) + зовнішній `codex review` — дозволений і там, де codex-maker заборонений смугою: заборона проти збірки, не проти читання (lanes.yaml — джерело, тут не кешується). Для широкого простору варіантів — лінзи з `decision-protocol.md`. Розбіжність рев'юерів — знахідка, називається окремо, не усереднюється.

   **Недоступність зовнішнього НЕ блокує роботу** (рішення CEO 08.08): правило, що блокує через чужий сервіс, почнуть обходити, а звичний обхід гірший за відсутнє правило. Деградація гучна, не тиха: у звіті «зовнішній рев'юер недоступний · <причина>», внутрішня перевірка піднімається в силі. Ціна чесно: 2–4 виклики замість одного, стеля субагентів діє й тут — не влазить склад, отже мерж завеликий, а не стеля замала.
7. **Прогрес у `portfolio.md` для стадії 5-Build — число з `engine/items/`.** Ручна оцінка розходилась із реєстром на дві позиції.
8. **Номер ADR — три листинги.** `ls` в обох `docs/adr/`, **плюс** `gh pr list --state open` → `git ls-tree --name-only <branch> docs/adr/` по кожному відкритому PR. Два цикли 04.08 незалежно взяли ADR-017, обидва виконавши старе правило правильно: номер справді був вільний на `main`, бо жоден PR не змержено.

## Зміна цього файлу доходить до сесій лише через реліз

Копія плагіна ключована версією; зміна без бампу невидима (05.08: копія від 7 липня без правил 7–11). Порядок: `scripts/release.sh` (бампає обидва маніфести) → `claude plugin marketplace update strw-factory` → `claude plugin update strw-factory@strw-factory` → `diff -rq ~/.claude/plugins/cache/strw-factory/strw-factory/<v>/loops loops` мовчить. `strw-run` перевіряє це в preflight; зміни діють з наступної сесії.
