# Нативні виходи — карта виходів фабрики → типи Artifact застосунку Claude

Звідки: слова CEO 28.10 («по типу Doc, Slides, Design, Dashboard»), елемент strw-state `factory.native-outputs`. Підбір
інструмента — у `strw-state/engine/tools.yaml` і `scripts/engine/tool-select.sh`; тут — який вихід яким типом стає.

**Виміряно 28.10** (`Artifact` · `action: list` · `scope: types`): рівно п'ять типів — Dashboard, Design, Design System,
Docs, Slides. Типи задає акаунт: зміна — перевиміряти, оновити файл і реєстр. `scripts/native/native-outputs-map.test.sh`
тримає п'ять розділів типів і рівно один рядок карти на кожен `vocab.task_types` реєстру.

## Що спільне для всіх п'яти

- **Приватно завжди.** Артефакт приватний, доки його не поділено з меню Share сторінки; сесія ділитися не може і не
  просить CEO «поділитися» сама. Поділитися, опублікувати назовні, надіслати посилання третій особі — рішення CEO
  (`strw-state/company-context.md`, принцип 5), не сесії.
- **Джерело правди — git.** Артефакт — подання, не стан: петлі читають файли з репо, не артефакти. Що в артефакті,
  те відтворюється генератором або файлом із git; посилання на артефакт живе тут або в елементі реєстру.
- **Без даних користувачів продуктів.** Жоден артефакт не отримує даних користувачів Pact і решти продуктів, доки CEO
  не ввімкнув таке джерело (принцип 5); конектор із такими даними в `tools.yaml` має `enabled_by: ceo`.
- **Не видаляти** (незворотно, ламає посилання) — лише на пряме прохання CEO. **Створює сесія, не скрипт:** генератор у
  `scripts/native/` готує дані, сесія публікує через `Artifact`/`ArtifactData`.

## Типи

### Dashboard
Сторінка чисел і таблиць над датасетами (живий запит конектора або доданий CSV/TSV/JSON). Створення: `Artifact` з
`type_url` типу, `title`, без файлів; наповнення — документи власного сховища (`dash/meta`, `datasets/<id>`,
`files/index.html`) через `ArtifactData`. Оновлення файлового датасету — нове завантаження (`asset: true`) і `update`
його `url`/`name`/`updated`. Не робити: числа в розмітці замість датасету; живий запит до конектора з даними
користувачів без рішення CEO; перенос дошки хаба (`reports/2026-10-20-status-board.md`) без рішення CEO.

### Design
Полотно з артбордами (екрани, макети, візуали). Не робити: робити полотно джерелом макетів Pact — L7 хешує канваси в
репо (`design/index.yaml`), а зміна поза git випадає з `strw-design-sync`; макет із полотна в код — лише через L7.

### Design System
Довідник бренду: README, токени, компоненти з живим переглядом. Не робити: правити токени в артефакті — джерело токенів
Pact у коді (`design_tokens`); довідник лише генерується з коду.

### Docs
Документ, який читають і правлять разом, експорт у .docx/PDF/Markdown; пишеться через конектор Claude Docs, не файлами.
Не робити: переносити туди звіти, які читають петлі (portfolio-brief, retro-note, build-report) — вони мусять лишатися в
git; Docs — хіба дзеркало для читання CEO, і лише після його рішення.

### Slides
Дека 16:9, завантажується як .pptx/PDF. Не робити: розсилати чи ділитися посиланням без CEO; деку з числами — лише з
числами, що мають джерело у git (portfolio, loops-log), не з пам'яті сесії.

## Карта

Рядок на кожен `vocab.task_types` реєстру — рівно один. «Куди»: один із п'яти типів, `файл` (лишається файлом у git) або
`—` (не вихід-документ: дія, код, розмова). «Статус»: `впроваджено` (працює зараз), `кандидат` (можна зробити без CEO
наступним елементом), `чекає CEO` (змінює канал CEO, публікацію або дані користувачів — принцип 5); для `—` — `—`.

## Живий Dashboard реєстру

**Приватний Dashboard «Реєстр інструментів STRW»:** https://claude.ai/artifact/ELmCJXr9kRpguLCwSN8qs7 (створено 28.10 з
типу Dashboard через `type_url`). Три файлові датасети: `summary` (один рядок підсумків), `tasks` (рядок на тип задачі),
`tools` (рядок на запис реєстру; явний перелік полів, без команд проб). Сторінка — `scripts/native/tools-dashboard/index.html`.

**Оновлення з реєстру** (сесія, після кожної зміни `strw-state/engine/tools.yaml`):
1. `python3 scripts/native/tools-dashboard-data.py --registry ~/Developer/STRW/strw-state/engine/tools.yaml
   --out <тека> --now <UTC зараз, YYYY-MM-DDTHH:MMZ> --label "strw-state engine/tools.yaml @ <sha коміту>"`.
   Код 2 — відмова з причиною й без файлів: дашборд не чіпати, причину — в реєстр (tool-registry).
2. Кожен із трьох JSON — `Artifact` · `asset: true` · `url` цього дашборда · `file_path` (окремим викликом на файл);
   sha256 у відповіді звірити з `shasum -a 256` виходу.
3. `ArtifactData` · `update` кожного `datasets/<id>` з новими `source.url`/`source.name` і `updated: {at, by}`
   (`if_version` — з останнього читання).
4. Read-back: `ArtifactData get datasets/<id>` і `Artifact read path:<asset id>` — вміст побайтно дорівнює виходу
   генератора; `data/users/me` · `check` типу.
5. Сторінка змінилась у git — `update files/index.html` її повним текстом. Дашборд не замінює ні реєстру, ні дошки хаба.
