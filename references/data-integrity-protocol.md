# Data Integrity Gate — верифікація даних і висновків (успадковано з grow-pm v1.13)

Обов'язковий для L2 Validation, L5 Portfolio і будь-якого артефакту з числами/трендами. Checker перевіряє КОЖЕН пункт; fail будь-якого = артефакт повертається maker'у.

## Чекліст
1. **Неповні періоди:** заборонена екстраполяція незавершеного місяця/кварталу як тренду. Кожне число — з явною анотацією періоду inline.
2. **Святкові/аномальні вікна:** порівняння YoY/MoM не через свята, розпродажі, force-majeure без явної примітки.
3. **Одноджерельні каскади:** висновок, що спирається на ОДНЕ джерело, не може породжувати ланцюг подальших тверджень. ≥2 незалежні джерела для ключових тверджень (TAM, попит, ціни конкурентів).
4. **Джерело кожної цифри:** лінк або «оцінка, метод: …». Цифра без походження = видаляється.
5. **Свіжість:** дані >12 міс для ринкових тверджень — позначаються як застарілі.
6. **Кореляція ≠ причинність:** причинні твердження вимагають механізму або експерименту.
7. **Публічність ≠ достовірність:** маркетингові матеріали конкурентів — джерело про позиціювання, не про факти.
8. **Самозвіт ≠ зовнішній факт:** самозвіт компонента про самого себе (scratch-файл задачі, власне поле статусу, власний лог успіху) — не джерело тверджень про зовнішній світ. Твердження про світ вимагає зовнішнього виміру; коли його нема — питання йде в секцію «Не встановлено» артефакту, а не в аргументацію (ретро W33: причину простою «встановили» з поля `compared_against` scratch-файлу, чиє ж поле `note` казало протилежне).

## Формат анотації
`<число> (<джерело>, <період>, довіра: висока/середня/низька)`

## Клас джерела `synthetic` — ніколи не evidence
Синтетичний сигнал — усе, що згенерувала модель від імені користувача: persona-card (predicted), вихід персона-панелі, імітований A/B, «інтерв'ю» з агентом. Правила (P2 концепту [[STRW_Persona_Layer_v1]]):
1. Synthetic НЕ може стояти в секціях «Сигнали попиту» (idea-card) і «Попит» (validation-report) — навіть з анотацією. Місце для нього одне: окрема секція «Синтетичні сигнали (не докази)».
2. Гейти G1–G4 на synthetic не спираються ніколи; він лише впорядковує чергу реальних проб.
3. Анотація: `<твердження> (synthetic: <персона/панель>, <дата прогону>, не для рішень)`. Панельний звіт з абсолютним прогнозом метрики без позначки «не для рішень» = FAIL checker'а (P3).
