# Self-Improvement Protocol — рівень фабрики (успадковано з grow-pm)

Застосовується: (а) наприкінці будь-якого skill після корекцій Andrii; (б) систематично — у L6 Retro Loop.

## Тригер
Andrii виправив вихід / вказав на помилку / попросив змінити структуру. НЕ тригериться на «ок, все добре» чи разові контентні правки.

## Кроки
1. **Виправити** те, що просили. Підтвердження.
2. **Root cause:** що пішло не так → чому (прогалина інструкції? відсутній крок? неврахований кейс?) → чи це ПАТЕРН чи one-off → скоуп (один skill / кілька / паспорт петлі / конституція).
3. **Пропозиція** (тільки якщо патерн): конкретна мінімальна зміна — «поточна поведінка → пропонована → як запобігає». Кілька — нумерованим списком на вибір.
4. **Регресія (обов'язкова перед застосуванням):** `bash scripts/evals/run.sh --offline` — golden мусять отримати PASS, seeded-фікстури (`references/evals/seeded/`) мусять бути зловлені з правильною причиною. Змістові дефекти — `STRW_EVALS_ONLINE=1 bash scripts/evals/run.sh`. Регресія не пройшла → зміна не застосовується. Гейт стоїть у pre-commit і `release.sh`, тож обійти його мовчки не можна.
5. **Застосування** (тільки з дозволу Andrii, після регресії): правка файлу → bump версії skill (PATCH/MINOR/MAJOR) → bump plugin.json за найвищим імпактом → запис у CHANGELOG.md плагіну → якщо змінено процес фабрики — запис у strw-state/process-changelog.md.

## Правила
- Мінімальна зміна, що закриває патерн. Без over-engineering.
- Чесність: one-off (унікальний контекст, смак користувача) — так і сказати, нічого не міняти.
- Зміни паспортів петель = MINOR мінімум; зміна структури петлі = MAJOR.
- **Інцидент класу «агент» стає фікстурою.** Помилка поведінки, яка повторилась удруге, дописується файлом у `references/evals/seeded/` з полем `source: <tri-/П- інцидент>` — інакше урок лишається анекдотом у прозі й повторюється втретє.
