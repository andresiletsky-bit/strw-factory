# STRW Dynamic Workflow Engine

Рушій, який виконує **декілька неконфліктуючих циклів розробки паралельно**, **переживає вичерпану квоту** без втрати роботи і **не блокується на рішеннях CEO**.

---

## 1. Проблема

Фабрика має зрілі петлі (L1–L6), розділення maker/checker, гейти й конституцію. Вузьке місце — не петлі.

**Робота ніде не існує в машиночитному вигляді.** `products/pact-001/state.md` — 64 КБ прози; «що далі» реконструюється щосесії з наративу плюс дев'ять рукописних промт-файлів (`m2-day-session-*.md`, `night-session-prompt-*.md`). З цього випливають рівно три спостережувані відмови:

| Симптом | Доказ | Причина |
|---|---|---|
| Нуль паралелізму | паспорт L3 дозволяє ≤2 worktree, де-факто працює 1 | немає способу знати, що незалежне |
| Нема відновлення після падіння | інцидент 27.07: три `.lock`, L1–L6 не писали стан з 08:09 до 14:01 | немає чекпойнта, з якого продовжити |
| Рішення гниють | 11 OPEN у `triage-inbox.md`, 0 рішень за 7 днів, найстаріше 18 днів, tea-001 G1 — третій тиждень топ-фокусом | немає черги з дефолтами й термінами |

Отже рушій — одна річ: **граф роботи стає артефактом першого класу.** Решта випадає з нього.

## 2. Цілі й не-цілі

**Цілі.**
1. N неконфліктуючих одиниць роботи виконуються одночасно, з повним циклом кожна (план → тести → код → детермінований гейт → рев'ю → PR → merge).
2. Вичерпана квота Claude звужує пропускну здатність, а не зупиняє фабрику; після відновлення робота продовжується автоматично, без участі людини.
3. CEO залучається лише там, де потрібне його рішення; питання накопичуються структуровано; незаблокована робота йде далі.
4. Проєктування й розробка — сильними моделями, перевірка — сильнішими; кожен великий етап проходить аудит кількома моделями, включно із зовнішньою.
5. Цикли й помилки вимірюються; співвідношення ціна/якість калібрується даними, а не відчуттям.

**Не-цілі.**
- Не автоматизуємо незворотні дії (гроші, прод-деплой, App Store, видалення даних, KILL продукту) — конституційний принцип №5 лишається чинним.
- Не замінюємо петлі L1–L6. Рушій — планувальник і виконавець над ними; паспорти лишаються джерелом правди про *зміст* роботи.
- Не будуємо власний CI. Гейти якості — наявні GitHub Actions / Xcode Cloud плюс локальні скрипти.
- Не робимо `triage-inbox.md` неактуальним. Він лишається append-only аудит-слідом.

**Наскрізний принцип: при сумніві — серіалізувати.** Паралелиться лише доведено незалежне. Недоведене йде в чергу, а не в паралель.

## 3. Модель даних

```
strw-state/engine/
├── lanes.yaml              # реєстр смуг — єдине джерело правди про конфлікти
├── items/<item-id>.yaml    # по файлу на одиницю роботи
├── decisions/<d-id>.yaml   # по файлу на питання до CEO
└── cycles/<YYYY-Www>.jsonl # машиночитна телеметрія циклів (append)
```

**Один файл на елемент, не спільний `queue.yaml`.** Це не естетика: інцидент 27.07 показав, що конкуренція за запис у стан — реальний, уже пережитий режим відмови. При N паралельних агентах спільний файл гарантує merge-конфлікти в стані. При файлі-на-елемент кожен агент пише **тільки свій** файл — нуль конкуренції.

### 3.1 Елемент роботи

```yaml
id: pact-001.m2.tokens          # стабільний, ієрархічний
product: pact-001
loop: L3-build
lane: ios-ui                     # одиниця конфлікту
title: "Design tokens → Swift + Manrope Cyrillic gate"
state: ready                     # ready|running|review|blocked|done|parked
blocked_by: [decision:d-014, item:pact-001.m2.xcodeproj]
repo: pact-ios
branch: feat/m2-tokens           # створює планувальник, НЕ maker
acceptance: |                    # верифікована stop-умова, не проза
  - xcodebuild test зелений (вивід пред'явлено)
  - жодного hardcoded hex поза token-файлом (lint-правило)
  - uk/de/pl рендеряться без tofu на симуляторі
maker: auto                      # auto → береться з lanes.yaml
checker: strw-code-reviewer
lease:
  run_id: null
  claimed_at: null
attempts: 0
history: []                      # компактні записи циклів, не наратив
```

`acceptance` — обов'язкове й **верифіковане**. Елемент без перевірюваної stop-умови не планується: це той самий інваріант, що вже діє в паспорті L3 («done від maker — заява; done петлі = stop_condition, перевірена checker'ом»).

### 3.2 Смуги

Смуга — одиниця конфлікту й одиниця WIP. **У смузі рівно один активний елемент.**

```yaml
- id: backend-contract
  repo: pact-backend
  owns: ["api/openapi.yaml", "docs/consensus-vectors.json"]
  blocks: [ios-ui, ios-platform]     # ADR-009: контракт спершу в backend
  codex_maker: allowed
  maker_model: codex/gpt-5.6-sol
  checker_model: opus-5/xhigh

- id: ios-ui
  repo: pact-ios
  owns: ["App/Features/**", "PactDesignKit/**"]
  codex_maker: forbidden
  codex_evidence: "дві проби 2026-07-20: CoreSimulator XPC заблоковано, xcodebuild завис >6хв"
  maker_model: sonnet-5
  checker_model: opus-5/xhigh
```

Дві смуги в **одному репо** можуть бути готові одночасно — тоді планувальник зобов'язаний **статично довести**, що їхні `owns` не перетинаються. Не довів — серіалізує. Це перетворює принцип «при сумніві не паралелити» на перевірювану умову замість наміру.

Смуги ловлять те, чого шляхи не ловлять. `backend-contract` і `ios-ui` не мають ані спільного файлу, ані спільного репо — але конфліктують семантично (ADR-009: зміна контракту йде backend-first, двома PR). Тому `blocks:` живе на смузі, а не на файлах.

**Стартовий реєстр смуг:** `backend-contract`, `backend-domain`, `shared-kmp`, `ios-infra`, `ios-ui`, `ios-platform`, `design`, `docs-adr`, `discovery` (L1), `validation` (L2), `growth` (L4), `portfolio` (L5/L6), `audit-backlog`.

### 3.3 Рішення

```yaml
id: d-014
opened: 2026-07-27T21:00Z
product: pact-001
class: reversible                 # reversible | irreversible
question: "Де живе shared/ (PactCore, KMP)?"
options:
  - key: ios
    label: "У pact-ios"
    consequence: "Господар успадковує drift-стик із векторами pact-backend"
  - key: separate
    label: "Окреме репо pact-shared"
    consequence: "Третій репо в оркестрації соло-CEO"
recommended: ios
rationale: "PactCore споживається клієнтом; тримати його поруч зі споживачем дешевше за третій репо в оркестрації соло-CEO"
revert_cost: "≈пів дня: перенести модуль + переписати Gradle-шляхи + оновити CI"
deadline: 2026-07-29T09:00Z       # тільки для reversible
blocks: [item:pact-001.m2.kmp-setup]
answer: null
```

**`options` + `recommended` + `rationale` + `revert_cost` — обов'язкові.** Питання без рекомендації — дефект петлі; гейт його не пропускає. Саме це перетворює «11 OPEN, 0 рішень» на 20 рішень за 10 хвилин: CEO не досліджує, він підтверджує або відхиляє.

## 4. Диспетчер

Динамічний воркфлоу, що запускається cron-тіком кожні 2–3 год цілодобово, а також вручну.

| Фаза | Дія | Модель |
|---|---|---|
| **0 Preflight** | git-health (`find .git -name '*.lock'`); реклейм протухлих лізів; budget-чек; проба квоти Claude; проба Codex (таймаут 60 с) | без моделі / haiku |
| **1 Plan** | зчитати items+lanes+decisions; застосувати протерміновані дефолти; обчислити готовий набір; довести попарну непересічність; зрізати до N; створити гілки | haiku |
| **2 Execute** | `pipeline()` — незалежний ланцюжок на елемент | opus / sonnet / codex |
| **3 Settle** | кожен ланцюжок пише свій item-файл; рядок у `cycles/`; нові питання в `decisions/`; факт у `budget.md`; commit+push | haiku |

Ланцюжок одного елемента у фазі 2:

```
A. maker (у власному worktree, isolation: worktree)
   ↓
B. детермінований гейт — БЕЗ моделі
   тести · lint · dep-audit · secret-scan · мутаційна проба піна
   FAIL → назад до A без витрати моделі-checker'а
   ↓
C. checker (інша модель, сильніша) проти acceptance + trace
   FAIL → назад до A (max 2 ітерації) → далі ескалація
   ↓
D. PR → merge на зеленому CI
```

**Мутаційна проба піна** у кроці B: перед тим як довіритись тесту, гейт мутує рядок продакшн-коду, який цей тест нібито закріплює, і вимагає, щоб тест **упав**. Тест, який переживає мутацію, не є контрактом.

Обсяг проби навмисно вузький — це **не** повне мутаційне тестування (дороге й повільне). Мутуються лише **нові та змінені** цим циклом тести, по одній цілі на тест, обрана з рядків, які diff цього ж циклу торкнувся. Тест, що пережив мутацію, не валить цикл автоматично: він позначається `unpinned` і йде на вхід checker'у як окремий пункт. Скрипт, дешево, і відсікає цілий клас фальшивого «зеленого» до того, як він з'їсть час checker'а.

### 4.1 Лізи — відновлення після падіння

Елемент при захопленні пише `state: running`, `lease.run_id`, `lease.heartbeat`. **Живий ланцюжок оновлює `heartbeat` на кожному переході стадії** (A→B→C→D). Фаза 0 наступного тіку повертає в `ready` (з `attempts += 1`) лише ті елементи, чий `heartbeat` старший за поріг — дефолт **90 хв**.

Heartbeat, а не проста позначка часу захоплення, — обов'язковий: тік ходить кожні 2–3 год, а ланцюжок елемента цілком може працювати довше за поріг. Без оновлення heartbeat наступний тік вкрав би елемент у **живого** воркфлоу й запустив ту саму роботу вдруге — рівно те дублювання, від якого ліза захищає. Поріг має бути більшим за найдовшу стадію, не за найдовший елемент.

Робота ніколи не губиться і ніколи не дублюється. **Це і є механізм безперервності.** `resumeFromRunId` у воркфлоу працює лише в межах однієї сесії й тому непридатний для переживання квоти — єдиний носій безперервності є черга на диску.

`attempts >= 3` → елемент у `parked` + запис у `decisions/` класу `reversible` з рекомендацією «розбити на дрібніше». Захист від нескінченного циклу на отруєному елементі.

### 4.2 Стеля паралелізму

**N = 3** (старт 2, підняття після першого чистого тижня). Не довільно: `subagent-delegation` дає ≤6 субагентів на fan-out, maker+checker на елемент — це 6–9 агентів при трьох. Збігається з WIP-лімітом 3 у `portfolio.md`.

## 5. Політика моделей

Токени розподілені асиметрично: **maker читає десятки файлів, пише код, ітерується — важкий бік; checker дивиться diff проти acceptance — легкий.** Найдорожча модель на легкому боці дешевша, ніж на важкому. Тобто «сильніший перевіряльник» імовірно виходить одночасно якісніше й дешевше за поточну розкладку.

| Клас роботи | Maker | Checker циклу |
|---|---|---|
| Codex-придатні смуги (backend-*, shared-kmp) | **Codex `gpt-5.6-sol`** (effort high) | Opus 5 `xhigh` |
| iOS-смуги | Sonnet 5 | Opus 5 `xhigh` |
| Критичне (архітектура/ADR, PRD, консенсус-домен, безпека, RLS) | Opus 5 | Opus 5 `max` + панель із 3 незалежних refuter'ів, вердикт більшістю |
| Скани, дедуп, тріаж, перевірка схем | Haiku 4.5 | скрипт, без моделі |

**Коли maker уже на найсильнішій моделі, «ще сильніший checker» тиром недосяжний — тоді сила береться шириною.** Три незалежні верифікатори з різними лінзами (коректність / безпека / чи справді відтворюється), кожен інструктований *спростувати*, вердикт більшістю. Панель того самого тиру строго сильніша за одного перевіряльника того самого тиру.

Модель не хардкодиться у воркфлоу — це поле смуги в `lanes.yaml`. Ребаланс = правка YAML.

## 6. Codex — друге джерело потужності

Codex працює як maker з 2026-07-15, конверт живе в git (`.codex/config.toml` в обох репо). Емпірично доведені межі:

| Факт | Доказ |
|---|---|
| `gpt-5.6-sol`, effort high, `sandbox_mode = workspace-write` | `.codex/config.toml` |
| **Не може писати `.git` взагалі** | перевірено 2026-07-16 (`git switch -c` падає) |
| **Не тягне iOS-тулчейн** — CoreSimulator XPC заблоковано, `xcodebuild` завис >6 хв | дві проби 2026-07-20 |
| **Тягне KMP/PactCore** — `jvmTest` через Gradle, мережу видано | `.codex/config.toml` pact-ios, 2026-07-21 |
| `strw-state` для нього read-only | перевірено, спроба запису = BLOCKED |

**Наслідок для оркестрації:** гілку створює планувальник ДО виклику Codex, коміт робить ПІСЛЯ хендбеку. Codex редагує файли й ганяє тести; історію не чіпає.

**Наслідок для квоти:** смуги на Codex не витрачають квоту Claude. Вичерпане 5-годинне вікно Claude перестає бути стоп-краном.

**Асиметрія ролей:** обмеження тулчейну стосується ролі **maker'а, не рев'ювера**. Рев'ювер читає diff, тести й пред'явлений вивід — симулятор йому не потрібен. Тому **зовнішній аудит Codex доступний на ВСІХ смугах**, включно з iOS.

## 7. Драбина рев'ю

| Рівень | Коли | Хто |
|---|---|---|
| **0** детермінований гейт | кожен цикл | скрипт: тести, lint, dep-audit, secret-scan, мутаційна проба |
| **1** checker циклу | кожен цикл | сильніша модель проти acceptance + trace |
| **2** аудит етапу | межа milestone / gate | панель Claude ×3 (коректність / безпека / відтворюваність) **+ незалежний аудит Codex** (`--sandbox read-only`) |
| **3** gate-review | G1–G4 | CEO |

**Правило розбіжності: коли панель Claude і Codex розходяться — автоматична ескалація до CEO.** Не усереднюється, не голосується. Два різні провайдери, що розійшлися — найсильніший сигнал «тут справді неоднозначно», який рушій здатен згенерувати. Прецедент: 2026-07-16 Codex відмовився стартувати, бо план обіцяв exactly-once, а транспорт давав at-most-once — це впіймала незалежність провайдера, не тир моделі.

## 8. Деградація без блокування

Рушій планує проти живих джерел потужності. Зупинка — лише на перетині.

| Claude | Codex | Поведінка |
|---|---|---|
| ✅ | ✅ | усе; Codex-смуги не їдять квоту Claude |
| ✅ | ❌ | усе; Codex-смуги падають на Claude-maker'а (швидкість та сама, квота витрачається швидше) |
| ❌ | ✅ | backend + shared-kmp їдуть далі; iOS-смуги чекають вікна |
| ❌ | ❌ | тік завершується чисто, лізи звільняються, наступний тік продовжує |

**Проба доступності** — раз на тік у фазі 0, не на елемент: `codex --version` + тривіальний `codex exec` із **жорстким таймаутом 60 с**. Кожен подальший виклик Codex теж під таймаутом; спрацював — вважаємо недоступним, падаємо на Claude, пишемо причину. Таймаут не косметичний: зависон під Codex >6 хв уже зафіксовано, і одна така пауза з'їдає весь тік.

**Деградація аудиту етапу** (найтонше місце — мовчазний пропуск зробив би «перевірено незалежним провайдером» неправдою):

1. Панель Claude розширюється з 3 лінз до 5 — часткова компенсація втраченої незалежності.
2. У записі етапу проставляється `external_audit: skipped` з причиною. **Ніколи мовчки.**
3. Створюється елемент у смузі `audit-backlog` — коли Codex повертається, етап аудитується заднім числом.

Гарантія не скасовується, вона відкладається. Флоу не блокується жодного разу й не бреше про своє покриття.

## 9. Черга рішень

`class: reversible` → дедлайн (дефолт +36 год); по його спливі застосовується `recommended`, запис у `decisions-log.md` з позначкою `auto-applied` і явною `revert_cost`.

`class: irreversible` → **без дедлайну, чекає скільки треба.** Тверда межа: гроші, прод-деплой, App Store submission, видалення даних, KILL продукту, зміна конституції. Це принцип №5 фабрики й межа асистента одночасно.

Розбір — скіл `/strw-decide`: показує по одному питанню через `AskUserQuestion`, пише `answer`, розблоковує залежні елементи, рендерить у `triage-inbox.md` для append-only аудиту.

**Заблокований елемент ніколи не блокує чергу** — планувальник просто його пропускає.

## 10. Калібрувальна петля

**Пастка вимірювання, без якої все це самообман: якість checker'а не можна оцінювати за його pass-rate.** Checker, що валить усе, виглядає прискіпливим. Нинішні 22% first-pass не кажуть нічого — це може бути слабкий maker, а може бути надто суворий checker, і зараз ці випадки нерозрізненні.

Розрізняє їх пара метрик, яких сьогодні немає:

- **Escape rate** — checker сказав PASS, дефект сплив пізніше (червоний CI після merge, борг у наступному рев'ю, баг у пізнішій фічі). Міра **недостатньої** сили.
- **Overturn rate** — checker сказав FAIL, зауваження виявилось хибним і його скасували. Міра **надлишкової** суворості й прямі спалені токени.

`state-protocol.md` §4a уже вимагає писати тривалість, ітерації maker↔checker, first-pass, вердикти й моделі M/C — схема правильна, але лежить прозою в тижневих `.md`, і L6 не може з неї рахувати. Рушій пише те саме в `engine/cycles/<YYYY-Www>.jsonl` машиночитно, плюс escape, overturn і токени на цикл.

L6 Retro щотижня рахує по кожній конфігурації смуги: first-pass, escape, overturn, токени на змерджений PR — і пропонує ребаланс моделей. Пропозиція **зворотна**, отже застосовується дефолтом після дедлайну, а не гниє.

**Правило зупинки, щоб не хитало:** зміна лише при n≥8 циклів на конфігурації; одна зміна на смугу за раз; після зміни лічильник обнуляється.

## 11. Режими відмови

| Відмова | Виявлення | Відновлення |
|---|---|---|
| Воркфлоу вмер (квота, застосунок, краш) | `lease.heartbeat` старший за 90 хв | елемент → `ready`, `attempts += 1` |
| Git-локи (пережито 27.07) | `find .git -name '*.lock'` у фазі 0 | прибрати; не вдалось — тік СТОП + `error` у чергу рішень |
| Codex завис | таймаут 60 с | позначити недоступним на тік, падіння на Claude |
| Merge-конфлікт паралельних PR | червоний CI / конфлікт | елемент → `ready` з нотаткою rebase; **повторний конфлікт у тій самій парі смуг → `owns` неправильні, питання CEO** |
| Отруєний елемент (циклиться) | `attempts >= 3` | `parked` + питання «розбити на дрібніше» |
| Дві смуги виявились конфліктними | збіг `owns` при плануванні | серіалізувати, питання про перегляд меж смуг |

## 12. Амендменти конституції

Рушій суперечить чинним документам у трьох місцях. Без амендментів фабрика й рушій розійдуться.

1. **`references/budget-policy.md` § Політика моделей.** Зараз: «дефолт: maker opus → checker sonnet». Стає: **checker сильніший або ширший за maker'а** (тир, або effort, або панель). Правило «maker ≠ checker» лишається. Рішення CEO 2026-07-27.
2. **`references/loop-passport.md`.** Життєвий цикл лишається, але петлі більше не запускаються поштучно — вони постачають **елементи в чергу**, а виконує їх диспетчер. Паспорт отримує поле `lanes:` — які смуги петля живить.
3. **`references/state-protocol.md` §4a.** `loops-log/YYYY-Www.md` лишається людським журналом; машинне джерело метрик переїжджає в `engine/cycles/*.jsonl`. L5/L6 читають друге, не перше.

Додатково: `subagent-delegation.md` ліміт ≤6 узгоджується зі стелею N=3 (6–9 агентів) — потрібне явне уточнення, що ліміт стосується fan-out усередині одного елемента, а не суми по паралельних елементах.
